# Morrows and LSM runtime integration

Morrows owns Task, Assignment, Run, Agent process, semantic state, and restart/cancel policy. LSM owns Logical Sessions, machine execution, Jobs, persistent shells, and audit. A Run has exactly one primary LSM Logical Session. Morrows launches Codex; Codex calls LSM MCP directly. Morrows uses LSM `/api/control` only to provision, observe, and clean up runtime resources.

This integration is optional. Start LSM in MCP service mode (`local-shell-mcp --mode mcp`) with loopback control and required Session capabilities (see LSM `docs/control-plane-api.md`), then set `MORROWS_LSM_CONTROL_URL`, `MORROWS_LSM_CONTROL_KEY`, and optionally `MORROWS_LSM_SUBJECT` (default `local-mcp-client`). The control URL must be numeric loopback HTTP. Morrows never passes its control key to Codex. It configures Codex `mcp_servers.lsm` and `env_http_headers` for a new Run scoped capability on every launch. This capability confines MCP calls to the Run's Session; code run by Codex can read its inherited environment, so this is not a secret boundary against Agent generated code.

Morrows provisions the Session with `idempotency_key=morrows:run:<run_uuid>`. The binding is unique and durable. Restarting the same Run retains its Session and rotates the capability; a new Run always receives a new Session and capability, even when resuming the same Codex conversation. The Agent may get or report its Session, but only the Morrows control path may start, finish, cancel, or delete it. LSM Goal Plans do not control Run status.

Unexpected Agent exit without `run_complete` moves `running → interrupted` and retains the Assignment. `MORROWS_AGENT_RESTART_GRACE_SECONDS` sets the explicit restart window; default is 600 seconds. There is no automatic Agent process retry. `POST /api/runs/{id}/restart` queues a new launch attempt for the same Run. On expiry, Morrows releases the Assignment, blocks new dispatch while cleanup is pending, revokes the capability, and retries LSM cleanup. Confirmed cleanup ends the Run as `failed` with `failure_reason=agent_restart_window_expired`; an unreachable node keeps it pending.

`POST /api/runs/{id}/cancel` revokes capability, stops the Agent, and asks LSM to stop active Jobs and persistent shells. LSM waits at most 30 seconds for ordinary in flight calls before cancelling the Session. Morrows marks the Run `cancelled` only after cleanup confirms. Legacy `launch_stop` remains a separate attempt operation and rejects LSM bound Runs.

The Run view shows Morrows status first and LSM execution as a drill down. `GET /api/runs/{id}/execution` returns the Session, Jobs, shells, audit, and evidence; `GET /api/runs/{id}/jobs/{job_id}/output` reads scoped Job output. `POST /api/runs/{id}/evidence` may associate multiple LSM audit entries, ranges, Jobs, or artifacts with one semantic event. LSM Job failure alone does not fail the Morrows Run. LSM hot audit and Job data have retention limits, so Morrows persists object references and semantic state independently.
